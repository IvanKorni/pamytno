# Правила документации

Документация живёт рядом с кодом и меняется в том же коммите, что и код.

## Карта документов

| Файл | Содержимое |
|---|---|
| `README.md` | что это, как запустить, как тестировать |
| `CLAUDE.md` | точка входа для AI-ассистента: команды и ссылки на правила |
| `docs/rules/*.md` | правила проекта (дополняются по ходу разработки) |
| `docs/modules/<module>.md` | карточка модуля |
| `docs/features/<NNN>-<name>.md` | карточка фичи |
| `openapi/<module>-api.yaml` | контракт REST API модуля |

## Карточка модуля `docs/modules/<module>.md`

1. Назначение (1–3 предложения).
2. Классы по пакетам — таблица «класс → ответственность». Добавил класс — добавь строку.
3. Таблицы БД модуля.
4. Публикуемые и принимаемые события.
5. Эндпоинты.

## Карточка фичи `docs/features/<NNN>-<name>.md`

1. Сценарий пользователя.
2. API (метод, путь, коды ответа).
3. Бизнес-правила и принятые решения.
4. Ошибки (`code` → когда возникает).
5. Тесты — списком по уровням: unit / модульные / интеграционные (имена классов).

Номер `NNN` — порядковый, по мере появления фич.

## Правила пополняются

Нашли повторяющуюся ошибку или договорились о новом подходе — добавьте правило в `docs/rules/`
и, если возможно, автоматическую проверку (Checkstyle или `ArchitectureRulesTest`).
