# Правила frontend

Frontend находится в `frontend/`: React + TypeScript + Vite. Структура и модули — `docs/modules/frontend.md`.
Автоматически проверяется ESLint (`frontend/eslint.config.js`), Prettier и `tsc` — всё входит в `npm run check`.

## Слои и модули

- Слои: `app → pages → modules → shared`, зависимости только сверху вниз.
- Модули `identity`, `topic`, `deck`, `learning` повторяют модули backend и **не импортируют друг друга** —
  только `shared`. Нужны данные двух модулей — их собирает страница (`pages`).
- Снаружи модуль доступен только через свой `index.ts`. Между слоями — импорт через алиас `@/`,
  внутри модуля — относительный.
- Модуль не знает о чужих ключах кеша: что перечитать в другом модуле, страница передаёт колбэком
  (`onCardsCreated`, `onDeleted`).

## Данные

- Компоненты не вызывают `fetch`: HTTP — только `request` из `shared/api/client.ts`, эндпоинты — в `modules/<module>/api/`.
- TanStack Query — server state; Zustand — только глобальный client state (пользователь, уведомления).
  Состояние одного экрана (учебная сессия, черновик формы) — локальный `useState` / `useReducer`: уходит вместе с экраном.
- Данные, от которых зависит расписание повторений (карточки к повторению), не берутся из кеша.
- Frontend не пересчитывает даты повторения — их считает backend.
- Типы DTO генерируются из `openapi/*.yaml` командой `npm run api:generate` в `src/modules/<module>/api/schema.gen.ts`
  и руками не правятся; `npm run check` падает, если контракт изменился, а типы нет (`api:check`).
- Долгие операции backend опрашиваются до `READY` или `ERROR` и перестают опрашиваться после; идущая задача
  переживает уход с экрана.
- Асинхронные операции обязаны иметь loading, success, error и empty state; ошибка мутации не теряется молча.
- Выход очищает кеш запросов.

## Размер — ничего не расползается

Проверяет ESLint. Упёрся в лимит — дроби компонент, хук или функцию по ответственности, а не ослабляй правило.

| Ограничение | Лимит |
|---|---|
| Длина файла | 200 строк (тесты — 250) |
| Длина функции или компонента | 40 строк без пустых и комментариев (JSX многословен) |
| Операторов в функции | 15 |
| Параметров функции | 5 (больше — объект) |
| Цикломатическая сложность | 8 (`&&`, `??`, `?.` в JSX тоже считаются) |
| Вложенность блоков | 2 |
| Вложенность колбэков | 3 |
| Длина строки | 120 (Prettier) |

## Стиль

- Prettier: без `;`, одинарные кавычки, 2 пробела, ширина 120. `npm run format` форматирует, `format:check` проверяет.
- `import type` для типов, `===`, никаких `any` и `console`.
- Текст интерфейса и описаний тестов — на русском; имена кода — на английском.

## Тесты

- Unit (`*.unit.test.ts`) — чистая логика: reducer-ы, политики опроса, форматирование.
- Module (`*.module.test.tsx`) — экран целиком с фейковым backend (`src/test/fakeBackend.ts`) через `renderApp`:
  всё приложение в StrictMode, как в браузере. Каждый исправленный баг — тест, который падал на старом коде.
- Integration (`*.integration.test.ts`) — HTTP-путь через настоящий backend при `VITE_PAMYTNO_INTEGRATION_URL`.
- Блоки `// given`, `// when`, `// then`.
- Перед маленьким коммитом — `npm run check` и integration-тест при доступном backend.
