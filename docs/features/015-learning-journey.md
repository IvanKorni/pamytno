# 015. Сквозной сценарий ТЗ §28

Проверяет критерий готовности Backend MVP целиком — по настоящему HTTP, через все модули.

## Сценарий `LearningJourneyIntegrationTest`

1. Регистрация и вход — дальше все запросы с токеном пользователя.
2. Тема + три источника: текст, PDF (генерируется в памяти `PdfFixtures`), YouTube (субтитры отдаёт WireMock).
3. Ожидание единого текста, в котором есть фрагменты всех трёх источников.
4. Генерация вопросов (заглушка `AiProvider`), одобрение всех вопросов.
5. Генерация карточек; карточки попадают в очередь повторения модуля `learning`.
6. Учебная сессия: REMEMBER по первой карточке — следующее повторение через день;
   FORGOT по второй — карточка остаётся в очереди и возвращается в сессию. Статистика сессии 1 / 1.
7. `TestClock` сдвигается на день — обе карточки снова к повторению.

Второй сценарий: удаление темы убирает её карточки из `deck` и из прогресса `learning`.

## Правила и решения

- Клиент `JourneyClient` ходит в приложение как фронт и не бросает исключений на 4xx — статусы проверяет тест.
- Асинхронные шаги (обработка источников, события между модулями, генерация) — только через Awaitility.
- Между модулями нет синхронных вызовов, поэтому генерация вопросов опрашивается до `202`:
  пока `deck` не получил `TopicContentPrepared`, он отвечает `409 TOPIC_CONTENT_NOT_READY`.
- Реальные внешние сервисы не вызываются: YouTube — WireMock, AI — `StubAiProvider`.

## Запуск

```bash
./gradlew integrationTest
```
