# 014. Прогресс изучения и dashboard

## Сценарий

1. На экране темы фронт показывает прогресс: `GET /api/topics/{topicId}/progress`.
2. На главном экране — общий итог и прогресс каждой темы: `GET /api/dashboard`.

## API

| Метод | Путь | Успех | Ошибки |
|---|---|---|---|
| GET | `/api/topics/{topicId}/progress` | 200 `TopicProgressDto` | 401 |
| GET | `/api/dashboard` | 200 `DashboardDto` | 401 |

## Правила и решения

- Состояния карточки:
  - новая — `totalReviews = 0`;
  - изученная — `stage >= 6`;
  - на изучении — всё остальное.
  CONTINUE не меняет прогресс, поэтому и `totalReviews` не увеличивает.
- `dueCards` — `nextReviewAt <= сейчас`; `dueToday` — `nextReviewAt` раньше полуночи следующего дня.
  «Сегодня» считается в часовом поясе приложения (`pamytno.time.zone`), а не в UTC.
- `progress` — изученные / всего × 100, округление до одного знака; для пустой темы — 0.
- Итог dashboard пересчитывается из сумм счётчиков, а не как среднее процентов тем.
- Счётчики всех тем считаются одним JPQL-запросом с `group by topic_id`. Прогресс темы — фильтр этого
  же результата: тем у пользователя немного, отдельный запрос не нужен.
- Тема без карточек (или чужая) отвечает нулями, а не 404: `learning` не знает о темах `topic`
  и не отличает «чужую» тему от «ещё без карточек». Утечки нет — чужие карточки не считаются.

## Тесты

- Unit: `ProgressStatsTest` — производные показатели, округление, пустой прогресс, сумма.
- Unit: `ProgressServiceTest` — граница «сегодня» в поясе приложения, тема без карточек.
- Модульные: `ProgressModuleTest` — прогресс темы по состояниям карточек, dashboard по своим темам,
  нулевой прогресс пустой темы.
