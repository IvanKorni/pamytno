# 006. Генерация вопросов

## Сценарий

1. Когда у темы готов единый текст, пользователь нажимает «Сгенерировать вопросы».
2. Backend отвечает `202` с задачей в статусе `PROCESSING`, фронт опрашивает `GET /api/generation-jobs/{id}`.
3. По каждому фрагменту актуальной версии текста AI предлагает вопросы с цитатой-источником.
4. Задача завершается `READY` (`itemsCreated` — сколько вопросов) или `ERROR` (`errorMessage`).

## API

| Метод | Путь | Успех | Ошибки |
|---|---|---|---|
| POST | `/api/topics/{topicId}/questions/generate` | 202 `GenerationJobDto` | 401, 409 |
| GET | `/api/generation-jobs/{jobId}` | 200 `GenerationJobDto` | 401, 404 |

## Правила и решения

- Генерация идёт по фрагментам (фича 005): текст может не помещаться в контекст модели.
- Вопрос хранит `chunkId` (связь с фрагментом) и `sourceFragment` — дословную цитату, на которой он основан.
  Если модель не дала цитату, источником считается весь фрагмент.
- Вопросы создаются в статусе `GENERATED`; пустые ответы модели отбрасываются.
- По теме одновременно может идти только одна генерация вопросов (`GENERATION_IN_PROGRESS`).
- Задача ставится внутренним событием `QuestionGenerationRequested` и выполняется `@Async` после коммита;
  вызовы AI идут вне транзакции, каждый фрагмент сохраняется своей короткой транзакцией.
- Ошибка AI на одном фрагменте останавливает задачу со статусом `ERROR`, уже созданные вопросы сохраняются.
- Логи: старт (сколько фрагментов), финиш (сколько вопросов, длительность), ошибки AI. Текст материала не логируется.
- Модель — через `AiProvider` (фича 009 для Claude); по умолчанию `AI_PROVIDER=stub`.

## Ошибки

| Код | Когда |
|---|---|
| `TOPIC_CONTENT_NOT_READY` | у темы нет фрагментов: текст не собран, пуст или тема чужая |
| `GENERATION_IN_PROGRESS` | генерация вопросов по теме уже идёт |
| `GENERATION_JOB_NOT_FOUND` | задачи нет или она чужая |
