# 002. Темы

## Сценарий

Пользователь создаёт тему («Spring Security»), видит список своих тем, меняет название или описание,
удаляет тему со всеми материалами.

## API

| Метод | Путь | Успех | Ошибки |
|---|---|---|---|
| GET | `/api/topics` | 200 | 401 |
| POST | `/api/topics` | 201, статус `DRAFT` | 400, 401 |
| GET | `/api/topics/{topicId}` | 200 | 401, 404 |
| PATCH | `/api/topics/{topicId}` | 200 | 400, 401, 404 |
| DELETE | `/api/topics/{topicId}` | 204 | 401, 404 |

## Правила и решения

- Тема принадлежит одному пользователю. Чужая тема отвечает `404`, как несуществующая.
- PATCH меняет только переданные поля; пустое описание удаляет его.
- Статус темы (`DRAFT → PROCESSING → READY/ERROR`) не задаётся через API — он вычисляется
  по источникам (фича 003).
- Удаление публикует `TopicDeleted`: модули `deck` и `learning` удаляют вопросы, карточки и прогресс темы.

## Ошибки

| Код | Когда |
|---|---|
| `VALIDATION_FAILED` | пустое или слишком длинное название |
| `TOPIC_NOT_FOUND` | темы нет или она чужая |

## Тесты

- Unit: `TopicTest`, `TopicDeletionServiceTest`.
- Модульные: `TopicModuleTest` — создание, список, изоляция пользователей, PATCH, валидация, удаление + событие;
  `DeckCleanupModuleTest`, `LearningCleanupModuleTest` — реакция модулей `deck` и `learning` на `TopicDeleted`.
