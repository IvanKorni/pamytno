# 013. Повторение карточек

## Сценарий

1. Фронт берёт очередь `GET /api/topics/{id}/reviews/due` — карточки, срок которых наступил.
2. Показывает вопрос, по «Показать ответ» — оборот. Пользователь выбирает «Вспомнил», «Не вспомнил»
   или «Дальше» (CONTINUE — перейти к следующей части карточки, это не оценка).
3. На каждый ответ — `POST /api/cards/{cardId}/review {result, sessionId}`; ответ содержит новый этап,
   дату следующего повторения и признак `returnToSession`.
4. Через время (день, неделя…) карточки снова появляются в очереди.

## API

| Метод | Путь | Успех | Ошибки |
|---|---|---|---|
| GET | `/api/topics/{topicId}/reviews/due?limit=100` | 200 `DueCardDto[]` | 400, 401 |
| POST | `/api/cards/{cardId}/review` | 200 `ReviewResultDto` | 400, 401, 404, 409 |

## Правила и решения

- Правила этапов и интервалов — фича 011.
- Очередь: `nextReviewAt <= сейчас`, самые давние первыми, до `limit` (1–500, по умолчанию 100).
- `returnToSession = true` после FORGOT: фронт показывает карточку ещё раз в этой же сессии; к тому же она
  остаётся в очереди (срок — сейчас).
- `sessionId` необязателен; если передан, сессия должна быть своей, незавершённой и той же темы.
- Если карточка только что создана и событие ещё не обработано, ответ вернёт `CARD_PROGRESS_NOT_FOUND` —
  фронт просто обновляет очередь.

## Ошибки

| Код | Когда |
|---|---|
| `CARD_PROGRESS_NOT_FOUND` | карточки нет в повторении пользователя |
| `LEARNING_SESSION_NOT_FOUND` | сессия не найдена или чужая |
| `LEARNING_SESSION_COMPLETED` | сессия уже завершена |
| `LEARNING_SESSION_TOPIC_MISMATCH` | карточка из другой темы, чем сессия |

## Тесты

- Unit: `ReviewServiceTest` — ответ + сессия, неизвестная карточка, сессия другой темы.
- Модульные: `ReviewModuleTest` — REMEMBER убирает карточку из очереди на день и через день (`TestClock`)
  она снова к повторению; FORGOT + CONTINUE и статистика сессии; завершённая сессия; изоляция пользователей.
