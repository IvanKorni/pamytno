# 005. Фрагменты единого текста

## Сценарий

Единый текст темы может не помещаться в контекст модели. Когда модуль `topic` публикует новую версию
текста, модуль `deck` делит её на фрагменты и хранит их для генерации вопросов.

## Правила и решения

- Фрагмент: `sequenceNumber` (с 1), `startOffset`/`endOffset` в едином тексте, `content` —
  ровно `text.substring(startOffset, endOffset)`. Текст фрагмента не меняется.
- Граница ищется во второй половине допустимой длины: пустая строка (абзац) → перевод строки → конец
  предложения (`. `, `! `, `? `) → жёсткий разрез (не посреди суррогатной пары).
- Длина — `AI_CHUNK_SIZE` символов (6000 по умолчанию).
- `deck` хранит проекцию `topic_materials`: последнюю версию текста темы. Это отличает «текста ещё нет»
  от «текст стал пустым» (все источники удалены) — в обоих случаях фрагментов актуальной версии нет.
- Обработка идемпотентна: повторно доставленная или устаревшая версия пропускается
  (события Modulith доставляются «как минимум один раз»).
- Фрагменты старых версий не удаляются: на них ссылаются уже созданные вопросы.

## Тесты

- Unit: `TextChunkerTest` (границы, жёсткий разрез, точность смещений), `TopicMaterialServiceTest`
  (первая версия, повтор/устаревшая версия, пустой текст).
- Модульные: `TopicMaterialModuleTest` — событие `TopicContentPrepared` публикуется через `Scenario`
  без модуля `topic`; актуальными становятся фрагменты последней версии; чужой владелец их не видит.
