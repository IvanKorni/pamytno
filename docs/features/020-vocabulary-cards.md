# 020. Карточки английских слов

## Сценарий

Пользователь учит английский. В теме он нажимает «Добавить слова», вставляет список слов или кусок текста
и пишет, что из него взять:

- просто список — карточка на каждое слово или выражение;
- «слова, выделенные жирным» — текст вставлен из учебника или сайта, жирное выделение при вставке сохраняется
  как `**слово**`;
- «коллокации» — AI сам находит устойчивые сочетания в тексте.

AI сразу составляет карточки, без этапа отбора вопросов:

| Сторона | Что на ней |
|---|---|
| лицевая | объяснение значения простым английским (B1), ниже — английское предложение с пропуском `_____` |
| оборотная | само выражение **жирным**, под ним русский перевод, ниже — перевод предложения на русский |

В режиме обучения пользователь видит объяснение и предложение, вспоминает слово, открывает ответ и отмечает
«Помню» / «Не помню» — дальше карточка живёт по обычному расписанию повторений.

## API

| Метод | Путь | Ответ |
|---|---|---|
| POST | `/api/topics/{topicId}/vocabulary/generate` | 202 `GenerationJobDto` (`type = VOCABULARY`) |

Тело: `{ "text": "…", "instruction": "…" }` — `text` от 1 до 20 000 символов, `instruction` до 500 символов
и необязательна. Статус задачи — `GET /api/generation-jobs/{jobId}`, карточки — `GET /api/topics/{topicId}/cards`.

## Правила и решения

- Карточки слов — обычные `Flashcard` с `front` / `back` в разметке фичи 018: модули `learning` и прогресс
  работают с ними без изменений. У карточки слова нет вопроса (`questionId = null`).
- Модель возвращает поля отдельно (`word`, `translation`, `definition`, `example`, `exampleTranslation`),
  а стороны карточки собирает домен (`WordCard`) — раскладка не зависит от того, как модель оформит ответ.
- Пропуск приводится к одному виду `_____`. Если модель вписала выражение вместо пропуска, оно заменяется
  пропуском; если пропуска нет и выражения в предложении нет или какое-то поле пустое — карточка пропускается.
- Один вызов модели на весь текст, не больше 50 карточек (`VocabularyRules.MAX_WORDS`). Правила промпта общие
  для Claude и CLI-провайдера (`VocabularyRules`).
- Выражение — в словарной форме, коллокация — целиком; пропуск закрывает всё выражение в той форме, в которой
  оно стоит в предложении. Если в материале есть понятное предложение с выражением — берётся оно.
  Перевод из списка «слово — перевод» сохраняется.
- Слова можно добавлять в тему без материалов. Чтобы проверить владельца такой темы, `deck` узнаёт о ней
  из события `TopicCreated` (проекция `topic_materials` с версией `0`). Тема, созданная до этой фичи и ни разу
  не получавшая материалов, модулю `deck` неизвестна — по ней ответ 404, пока в неё не добавят материал.
- Одновременно по теме идёт не больше одной задачи слов (`GENERATION_IN_PROGRESS`); вопросы и карточки по вопросам
  запускаются независимо.
- Картинки не поддерживаются — только текст.

## Ошибки

| Код | Когда |
|---|---|
| `VALIDATION_FAILED` (400) | пустой или слишком длинный текст, слишком длинная инструкция |
| `TOPIC_NOT_FOUND` (404) | темы нет, она чужая или неизвестна модулю `deck` |
| `GENERATION_IN_PROGRESS` (409) | карточки слов по теме уже составляются |

Ошибка модели не отвечает HTTP-ошибкой: задача переходит в `ERROR` с `errorMessage`.

- Unit: `WordCardTest` — стороны карточки, пропуск, выражение вместо пропуска, неполный ответ;
  `VocabularyGenerationServiceTest`, `VocabularyGenerationWorkerTest`, `FlashcardWriterTest`,
  `TopicMaterialServiceTest` (регистрация темы, `requireTopic`); `AnthropicAiProviderTest`, `CliAiProviderTest`,
  `StubAiProviderTest` — промпт и разбор ответа.
- Модульные: `VocabularyGenerationModuleTest` — карточки по жирным словам, чужая тема, пустой текст;
  `TopicMaterialModuleTest` — регистрация темы по `TopicCreated`; `TopicModuleTest` — публикация `TopicCreated`.
- Интеграционные: `VocabularyJourneyIntegrationTest` — новая тема → список слов → карточки к повторению.
- Вручную: промпт прогнан через codex CLI (`gpt-5.6-luna`) — текст с жирными словами, коллокации в тексте,
  список «слово — перевод».
